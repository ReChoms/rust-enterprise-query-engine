Semantic RAG Pipeline & Anti-Hallucination Engine

This panel breaks down the exact data transformations happening at each stage of the semantic retrieval pipeline.

Phase 1: Semantic Vector Retrieval

1. Intent & Filter Extraction: The raw query is parsed to isolate semantic intent (e.g. "customers in Berlin") from exact negative filters (e.g. NOT DE).

2. In-Process Candle Embeddings: candle-core generates 768-dimensional normalized dense vectors using local HuggingFace Safetensors without Python runtime dependencies.

3. LanceDB kNN Search: Retrieves top-k nearest neighbor vector chunks and stores them in an $O(1)$ lookup HashMap<String, Arc<str>>.

4. Anti-Hallucination Firewall: Rather than using secondary AI checks, Rust executes a physical byte-for-byte substring check:

let source_text = retrieved_chunks.get(&payload.source_chunk_id);
if !source_text.contains(&payload.exact_quote) {
    bail!("SECURITY VIOLATION: Hallucination detected.");
}

Phase 2: Literal Keyword Fallback (Absence Proofing)

If Phase 1 fails (either because answer_found was false, or the AI hallucinated), the engine triggers an exact SQL keyword search across LanceDB:

// Internal SQL Execution
"sentence LIKE '%Berlin%' AND sentence LIKE '%Bakeries%'"

If the fallback search yields zero matches, the system mathematically proves that the requested information does not exist in the corpus, preventing fabricated answers.
